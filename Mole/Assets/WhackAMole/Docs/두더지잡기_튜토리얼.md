# 두더지 잡기 — Inspector로 완성하는 3회 실습

대상 프로젝트: Unity 6000.4.2f1, 2D URP, Input System 1.19.0, UGUI 2.0.0. 코드는 `Assets/WhackAMole/Scripts`에 모두 제공되어 있다. 수강생은 코드를 작성하지 않고 Hierarchy 생성, 프리팹 제작, 컴포넌트 추가와 Inspector 참조 연결만 수행한다. 세 강의는 같은 Scene을 이어서 편집한다. 각 강의 종료 시 Scene을 저장한다.

## 준비: 프로젝트와 파일 확인

1. Unity에서 프로젝트를 열고 스크립트 임포트가 끝날 때까지 기다린다. Console의 컴파일 오류가 없어야 한다.
2. Edit > Project Settings > Player > Other Settings > Configuration > Active Input Handling을 **Input System Package (New)**로 선택한다. 재시작 안내가 나오면 재시작한다. Both도 동작하지만 이 강의는 New 기준이다. Package Manager에서 Input System과 Unity UI가 설치되어 있는지 확인한다. 현재 프로젝트에는 이미 포함되어 있다.
3. File > New Scene에서 Basic 2D (URP) 또는 기존 `Scenes/SampleScene`을 사용하고, Save As로 `Assets/Scenes/WhackAMoleTutorial.unity`에 저장한다. 기존 Global Light 2D는 유지한다.
4. `WhackAMole/Art/Mole`의 Idle, Up, Hit, Down PNG를 확인한다. 모두 Texture Type = Sprite (2D and UI), Sprite Mode = Single, Pixels Per Unit = 100을 사용한다. 변경했다면 Apply한다. 제공 이미지의 큰 투명 여백 때문에 SpriteRenderer의 표시 크기와 Collider 크기는 별도로 조절한다.

제공 파일의 역할:

| 파일 | 역할 |
|---|---|
| BoardConfig.cs / Configs/DefaultBoardConfig.asset | 행·열, 간격, 시간, 점수와 랭크 기준 |
| BoardLayout.cs | Config로 로컬 위치 배열 계산, 편집 모드 Gizmos, 실행 시 두더지 복제 |
| Mole.cs | Hidden → Rising → Up → Hit/Falling → Hidden 상태, 피격 이벤트 |
| GameManager.cs | 순서대로 등장, 제한 시간, 점수, 라운드 종료, Best 저장 |
| MolePointerInput.cs | 새 Input System 마우스 입력 → ScreenPointToRay → 2D 물리 판정 |
| GameHud.cs | 남은 시간·점수·빗맞춤 표시 |
| ResultBoard.cs | 결과 패널 이동·스케일·투명도·점수 카운트 애니메이션, 재시작 |

## 1강 — 배경, BoardConfig와 순차 등장

목표: 설정 에셋 하나로 3×3 위치 배열을 만들고, Art의 두더지가 왼쪽 위부터 행 우선 순서로 등장한다.

### 1. 카메라와 배경

1. Main Camera를 선택한다. Transform Position `(0, 0, -10)`, Rotation `(0, 0, 0)`, Scale `(1, 1, 1)`. Camera Projection = Orthographic, Size = 5, Clipping Planes Near = 0.3 / Far = 1000. Background는 연한 하늘색을 선택한다. 카메라 Tag는 MainCamera로 둔다.
2. Game 뷰의 비율을 16:9로 설정한다.
3. Hierarchy 우클릭 > 2D Object > Sprites > Square를 만들고 `Background`로 이름을 바꾼다. Position `(0,0,1)`, Scale `(18,10,1)`. SpriteRenderer Color를 잔디색으로 바꾸고 Order in Layer = -10으로 설정한다. Collider는 붙이지 않는다.
4. 조명에 영향을 받지 않는 실습을 원하면 SpriteRenderer의 Material을 `Sprite-Unlit-Default`로 선택한다. 검색되지 않으면 Project 우클릭 > Create > Material로 `MoleUnlit`을 만들고 Shader를 `Universal Render Pipeline/2D/Sprite-Unlit-Default`로 선택한다. 배경과 두더지에 이 Material을 사용한다.

### 2. 두더지 원본 프리팹 만들기

1. Hierarchy > Create Empty로 `Mole`을 만든다. Position `(0,0,0)`, Rotation 0, Scale `(0.16,0.16,1)`. 원본 이미지가 약 1254px/100PPU이므로 렌더 영역은 약 2 유닛이 된다.
2. Add Component > Sprite Renderer를 추가한다. Sprite에 `Art/Mole/Up`을 넣고 Color = White, Order in Layer = 1, Material은 위에서 준비한 Unlit을 지정한다.
3. Add Component > **Mole**을 추가한다. RequireComponent에 의해 Box Collider 2D도 자동으로 붙는다.
4. Mole의 Idle Sprite / Up Sprite / Hit Sprite / Down Sprite에 각각 같은 이름의 PNG를 연결한다. Inspector에서 이미지 파일을 드래그한다.
5. Box Collider 2D의 Is Trigger는 끄고 Offset `(0,0)`, Size `(7,7)`로 설정한다. Transform 스케일 반영 후 약 1.12×1.12 유닛의 타격 영역이다. Scene에서 Edit Collider로 실제 얼굴에 맞춰 조절할 수 있다. Rigidbody 2D는 필요 없다. 정적인 Collider에 물리 Ray를 쏘는 방식이다.
6. Inspector 상단 Layer > Add Layer에서 빈 User Layer에 `Mole`을 만든다. 돌아와 Mole 오브젝트의 Layer를 Mole로 지정한다.
7. Project의 `Assets/WhackAMole` 아래 `Prefabs` 폴더를 만들고 Hierarchy의 Mole을 드래그하여 `Mole.prefab`을 만든다. **Scene의 Mole 원본은 삭제한다.** 프리팹은 비활성화하지 않는다.

### 3. BoardConfig 연결과 자동 배열 확인

1. Project > `WhackAMole/Configs/DefaultBoardConfig`를 선택한다. 이미 만들어 둔 ScriptableObject다. 별도 설정은 Project 우클릭 > Create > Whack A Mole > Board Config로 만들 수 있다.
2. 기본값을 아래 표와 맞춘다.

| Inspector 필드 | 값 | 의미 |
|---|---|---|
| Rows / Columns | 3 / 3 | 총 9개 위치 |
| Spacing | X 2.5, Y 2 | 가로·세로 간격, 보드의 로컬 좌표 단위 |
| Center | 0, 0 | 보드의 로컬 중심 |
| Game Seconds | 30 | 라운드 길이 |
| Up Seconds | 0.8 | 타격 가능한 시간 |
| Transition Seconds | 0.15 | 등장·피격·퇴장 상태의 대기 시간 |
| Interval Seconds | 0.25 | 한 두더지가 숨은 뒤 다음 등장까지 대기 |
| Points Per Hit | 100 | 명중 1회 점수 |
| Rank A / Rank S | 1000 / 2000 | A와 S의 최소 점수 |

3. Hierarchy > Create Empty로 `Board`를 만든다. Position/Rotation 0, Scale 1. Add Component > Board Layout.
4. Config에 DefaultBoardConfig, Mole Prefab에 제작한 Mole.prefab을 드래그한다.
5. Scene 뷰의 Gizmos를 켠다. 노란 원 9개가 보인다. Board Layout의 Local Positions를 펼치면 9개의 좌표가 확인된다. 중심 0 기준 첫 좌표는 `(-2.5,2,0)`, 마지막은 `(2.5,-2,0)`이다.
6. Config의 Columns를 4로 변경한다. 배열이 12개로 바뀌고 원도 12개가 되는지 확인한 뒤 3으로 되돌린다. 편집 모드에서는 생성 위치만 미리 보여주며 프리팹 오브젝트는 Play 시 생성된다. Board를 이동·회전·확대하면 해당 로컬 위치들이 함께 변환된다.
7. Hierarchy > Create Empty로 `GameManager`를 만들고 Game Manager 컴포넌트를 추가한다. Board 필드에 Hierarchy의 Board를 연결한다. Auto Start = On, Save Best = **Off**로 둔다(1강 시연 점수는 저장하지 않음).
8. Play한다. Board 아래에 Mole_00~Mole_08이 생성되고 순차적으로 하나씩 등장한다. 이 단계에는 입력이 없어 점수는 변하지 않는다. 30초 후 모두 숨는다.

이 강의의 등장은 스프라이트 상태 교체로 표현한다. Animator나 별도 이동 애니메이션은 필요 없다. Idle은 숨김 상태에 할당되므로 화면에는 나타나지 않는다. Rising/Falling에는 Down, Up에는 Up, Hit에는 Hit 이미지를 사용한다.

**완료 점검:** 행·열 변경에 따른 배열/Gizmos 자동 갱신, 런타임 자식 개수, 등장 순서를 확인한다. Config 변경은 편집 모드에서 수행한다. 라운드 시작 시 규칙을 복사하므로 실행 중 설정 변경은 다음 라운드 시작에 반영된다. 보드 크기는 최대 20×20으로 제한된다.

## 2강 — 새 Input System, ScreenToRay와 타격

목표: 마우스 왼쪽 클릭으로 Up인 두더지만 맞추고, 제한 시간 동안 명중·빗맞춤을 집계한다.

### 1. 입력과 물리 판정 연결

1. Play를 종료한다. GameManager 오브젝트에 Add Component > Mole Pointer Input을 추가한다.
2. World Camera에 Main Camera, Game에 같은 오브젝트의 Game Manager 컴포넌트를 연결한다.
3. Mole Layers 드롭다운에서 Nothing을 먼저 선택하고 Mole만 체크한다. Ray Distance = 100.
4. 프리팹의 Layer가 Mole인지, Box Collider 2D가 있는지 다시 확인한다. 3D Box Collider는 이 코드와 호환되지 않는다.
5. 입력 코드는 `<Mouse>/leftButton` 액션을 생성하고 OnEnable/OnDisable에서 활성화/해제한다. 기존 InputSystem_Actions 에셋이나 PlayerInput 컴포넌트를 연결할 필요는 없다.

물리 판정 흐름은 `Mouse.current.position`(화면 픽셀) → `Camera.ScreenPointToRay`(3D Ray) → `Physics2D.GetRayIntersection`(2D Collider 교차) → `Mole.TryHit` → 성공 시 점수 갱신이다. 이 실습의 물리 이벤트는 **RaycastHit2D 기반 피격 판정과 onHit UnityEvent**다. OnCollisionEnter2D 접촉 이벤트를 사용하는 방식은 아니다.

### 2. 피격 이벤트를 Inspector에서 연결

1. Mole.prefab을 더블 클릭해 Prefab Mode로 연다.
2. Mole 컴포넌트의 On Hit 이벤트 아래 `+`를 누른다.
3. 같은 프리팹 루트 Mole 오브젝트를 대상 슬롯에 드래그한다.
4. 함수 드롭다운에서 SpriteRenderer > color (Color)를 선택하고 붉은색을 지정한다. 타격 시 Hit 이미지와 함께 색이 바뀌는지 관찰할 수 있다.
5. 동작 확인 후 이 이벤트 항목은 `-`로 지운다. 색상 변경을 계속 두면 다음 등장에도 붉은색이 유지되기 때문이다. 최종 실습은 Hit 스프라이트 자체로 피드백을 준다. On Hit에는 추후 AudioSource.Play 같은 연출을 추가할 수 있다.
6. Prefab Mode를 나가고 저장한다. 점수는 GameManager가 성공한 TryHit 반환값으로 한 번만 더하므로 On Hit에 별도 점수 함수를 연결하지 않는다.

### 3. UGUI HUD 만들기

1. Hierarchy 우클릭 > UI > Canvas. 이름은 `GameCanvas`. Render Mode = Screen Space - Overlay.
2. Canvas Scaler의 UI Scale Mode = Scale With Screen Size, Reference Resolution `(1920,1080)`, Screen Match Mode = Match Width Or Height, Match = 0.5.
3. 자동 생성된 EventSystem을 선택한다. Standalone Input Module이 있다면 제거하고 **Input System UI Input Module**을 추가한다. Actions Asset이 비어 있으면 Assign Default Actions 버튼을 누른다. 이미 Input System UI Input Module이 있으면 유지한다.
4. Canvas 아래 UI > Legacy > Text를 만들고 `HUDText`로 이름을 바꾼다. TextMeshPro가 아닌 **UnityEngine.UI.Text**를 사용한다.
5. RectTransform의 Anchor Min/Max `(0.5,1)`, Pivot `(0.5,1)`, Pos X = 0, Pos Y = -30, Width = 1500, Height = 100. Text Font = LegacyRuntime(또는 제공 기본 폰트), Font Size = 40, Alignment = Middle Center, Color = White. Raycast Target = **Off**.
6. GameManager에 Game Hud 컴포넌트를 추가한다. Game에 GameManager, Label에 HUDText를 연결한다.
7. Game Manager의 Save Best = On으로 바꾼다.

### 4. 플레이와 판정 규칙

- Game 뷰를 클릭해 포커스를 준다. Up 이미지의 얼굴을 클릭하면 100점, Hits 1 증가, Hit 이미지로 전환된다.
- 빈 배경, 숨은 두더지 위치, Rising/Falling 중 클릭하면 Misses가 1 증가한다. 같은 두더지를 연속 클릭하면 첫 클릭만 성공하며 다음 클릭은 빗맞춤이다.
- 누르고 있는 동안 자동 연타하지 않는다. 클릭을 새로 누를 때 한 번만 판정한다.
- 두더지를 놓쳐서 내려가게 두는 것은 클릭 빗맞춤으로 세지 않는다. 감점도 없다.
- Up 상태에서만 Collider가 켜진다. TryHit도 State를 다시 검사하여 중복 점수를 막는다.
- UI 위 클릭과 종료 후 클릭은 점수·빗맞춤에 포함하지 않는다. HUD의 Raycast Target을 끄는 이유는 HUD가 게임 클릭을 막지 않게 하기 위함이다.
- Remaining이 0이 되면 생성 코루틴을 중단하고 모든 두더지와 Collider를 숨긴다. 프레임 경계에서는 GameManager가 알고 있는 Remaining을 기준으로 판정한다.

**완료 점검:** Up 명중, 같은 두더지 두 번 클릭, 빈 곳 클릭, 클릭 없이 시간 경과, 종료 후 클릭을 각각 확인한다. 점수가 안 오르면 Mole Layer 마스크, Collider 2D, 카메라 참조, Play 여부, UI Raycast Target을 확인한다.

## 3강 — UGUI 결과 보드와 절차적 애니메이션

목표: 타이머 종료 이벤트로 결과 보드를 나타내며 빗맞춤·총점·Best·랭크를 표현한다. UI는 수강생이 미리 배치하고, 종료 시 코드가 투명도·위치·스케일을 절차적으로 계산하여 화면에 나타낸다. UI 오브젝트를 런타임에 Instantiate하는 예제는 아니다.

### 1. 결과 UI 배치

1. Play를 종료한다. GameCanvas 아래 Create Empty로 `ResultRoot`를 만든다. RectTransform Anchor Min `(0,0)`, Max `(1,1)`, Left/Right/Top/Bottom 모두 0. Scale 1.
2. ResultRoot에 Canvas Group을 추가한다. Alpha = 1, Interactable/Blocks Raycasts = On으로 두고 편집한다. 실행 시작 시 코드가 숨긴다.
3. ResultRoot 아래 UI > Image를 만들고 `Dim`으로 이름을 바꾼다. Stretch/Stretch 앵커, 모든 오프셋 0. Color는 검정, Alpha = 0.65. Raycast Target = On. 게임 영역 전체를 덮어 결과 화면 뒤 클릭을 막는다.
4. ResultRoot 아래 UI > Image로 `Panel`을 만든다. Dim의 자식이 아니라 **다음 형제**로 둔다. Anchor Min/Max/Pivot 모두 `(0.5,0.5)`, Pos `(0,0)`, Width = 800, Height = 720, Scale 1. Color는 짙은 남색, Raycast Target = On.
5. Panel 아래 UI > Legacy > Text를 만들고 `ResultText`로 바꾼다. Anchor Min/Max `(0.5,0.5)`, Pivot `(0.5,0.5)`, Pos `(0,60)`, Width = 720, Height = 520. Font Size = 48, Alignment = Middle Center, Color White, Raycast Target = Off. Text에는 임시로 `RESULT`를 입력한다.
6. Panel 아래 UI > Legacy > Button을 만들고 `RestartButton`으로 바꾼다. Anchor Min/Max/Pivot `(0.5,0.5)`, Pos `(0,-270)`, Width = 320, Height = 90. 자식 Text는 `RESTART`, Font Size = 32, Color = Black. Button의 On Click은 비워 둔다. 코드가 리스너를 연결한다.
7. GameManager에 **Result Board** 컴포넌트를 추가한다. 반드시 ResultRoot 밖의 활성 오브젝트에 둔다.

| Result Board 필드 | 연결할 Hierarchy 대상 |
|---|---|
| Game | GameManager |
| Group | ResultRoot의 CanvasGroup |
| Panel | Panel의 RectTransform |
| Result Text | ResultText의 Text |
| Restart Button | RestartButton의 Button |
| Duration | 0.65 |

8. ResultRoot, Panel, ResultText, RestartButton은 모두 활성화 상태로 둔다. CanvasGroup으로 보이기만 제어한다.

### 2. 결과 연출 확인

1. Config Game Seconds를 테스트용 5로 바꾼 뒤 Play한다. 결과 보드가 처음에는 보이지 않고 클릭도 막지 않는지 확인한다.
2. 5초 동안 몇 번 클릭한다. 종료 시 0.65초 동안 패널이 아래쪽 Y=-180에서 중앙으로 이동하고 크기가 0.7에서 1로 커진다. 동시에 ResultRoot Alpha가 0에서 1로 바뀌고 점수가 0에서 실제 점수까지 올라간다.
3. 이동/크기는 cubic ease-out, 투명도는 선형이다. Animator, AnimationClip, DOTween 없이 Coroutine과 보간으로 구현되어 있다. Time.unscaledDeltaTime을 사용하므로 UI 연출 자체는 Time.timeScale의 영향을 받지 않는다.
4. HITS는 명중 수, MISSES는 클릭 빗맞춤 수, SCORE는 최종 점수, BEST는 기존 기록과 이번 점수 중 큰 값이다. 랭크는 마지막에 표시한다.
5. 점수가 Rank S 이상이면 S, 그 외 Rank A 이상이면 A, 나머지는 B다. 기본 30초/순차 등장에서는 한 두더지의 상태 시간과 간격 때문에 획득 가능한 점수에 상한이 생긴다. 강의 시 S를 쉽게 시연하려면 Rank A = 300, Rank S = 600으로 조절한다.
6. RESTART를 누르면 패널이 숨고 새 보드로 즉시 다시 시작한다. Hits/Misses/Score와 타이머는 초기화되고 Best는 유지된다. 입력과 HUD도 다시 동작하는지 확인한다.
7. Play를 종료하고 Game Seconds를 30, 랭크 기준을 원하는 강의 값으로 되돌린 후 Scene을 저장한다.

Best는 PlayerPrefs의 `WhackAMole.Best.v1` 키로 로컬에 저장하며 라운드 종료 시 저장한다. Save Best를 끄면 그 라운드는 기록을 디스크에 쓰지 않지만 기존 기록은 읽는다. 에디터와 빌드는 저장 위치가 다를 수 있다. 기존 기록을 포함하여 전체 PlayerPrefs를 지우는 에디터 메뉴는 다른 실습 데이터도 지우므로 이 강의에서는 사용하지 않는다.

## 강의자 최종 검증표

| 확인 항목 | 기대 결과 |
|---|---|
| 편집 모드 Config 2×4로 변경 | Local Positions와 Gizmos가 8개, 다음 실행 시 두더지 8개 |
| Board 이동 | 자식 두더지 위치가 Board 기준으로 이동 |
| Play 시작 | 결과 UI 숨김, 0점, 타이머 시작 |
| 첫 두더지 Up 클릭 | Hit 이미지, 명중 1, 100점 |
| 숨은 곳/빈 곳 클릭 | 빗맞춤 증가, 점수 유지 |
| Up 두 번 클릭 | 성공 1회, 이후는 빗맞춤 |
| 시간 초과 | 모두 숨김, 추가 점수 차단, 결과 연출 |
| 랭크 경계 300/600으로 테스트 | 300점 A, 600점 S, 300점 미만 B |
| 재시작 | 보드 재생성, 카운트 초기화, 결과 숨김 |
| 종료 후 다시 Play | 저장한 Best 유지 |

한 화면에서 위치가 겹치면 Spacing이나 프리팹 Scale을 조절한다. Config를 크게 만들면 카메라 Size도 직접 늘린다(자동 카메라 맞춤은 이 실습 범위에 포함하지 않는다). 검은 화면은 카메라 Z/회전, 보이지 않는 스프라이트는 Material/조명과 참조를 확인한다. 결과 화면이 클릭을 막으면 EventSystem 입력 모듈 및 ResultRoot의 CanvasGroup 연결을 확인한다. UI 텍스트가 할당되지 않으면 TMP 대신 Legacy Text를 만들었는지 확인한다.
